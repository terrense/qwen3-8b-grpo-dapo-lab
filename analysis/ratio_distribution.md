# Importance ratio 的真实分布 —— 我之前那个结论是错的

**先说结论：我说的「ρ ≈ 1，所以 GSPO 在这个配置下测不出东西」是错的，撤回。**

实际分布**尖峰厚尾**：一半的 token 几乎不动（|ρ−1| 中位数 ~3e-6），但有 **8% 的 token
偏离超过 1%**，极值到 **±30~42%**。这个离散程度对 GSPO 的论点来说完全够用。

`clip-higher 没什么可作用的` 这条结论**保留**，但理由变了 —— 不是因为分布窄，
而是因为 (1.2, 1.28] 这个窄带里 token 太少。

---

## 怎么错的

我看的是这两个数：

```
actor/ppo_kl      ~1e-5      看着像 0
actor/pg_clipfrac ~1e-4      看着像没有 clipping
```

然后推出「ρ 恒等于约 1」。**两个推理都不成立**：

**`ppo_kl` 是带符号均值。** `core_algos.py:1339`：

```python
negative_approx_kl = log_prob - old_log_prob
ppo_kl = verl_F.masked_mean(-negative_approx_kl, response_mask)
```

均值接近 0 既可能是分布窄，也可能是正负偏差互相抵消。

**这次直接量到了抵消的证据** —— 三个 update 的 `ppo_kl` 符号在翻：

| step | `ppo_kl` |
|---|---|
| 1 | **+**5.096e-05 |
| 2 | **−**4.937e-05 |
| 3 | **+**3.090e-05 |

一个真正「窄」的分布不会这样来回翻符号，它会稳定贴近 0。翻符号说明每步都有
可观的正负偏差在打架，只是加起来差不多抵消了。

**`pg_clipfrac` 只数越过 ±0.2 的尾巴。** 它对边界以内的形状一无所知 ——
而 1%~5% 这个区间恰恰是 GSPO 关心的地方。

讽刺的是我在自己写的 [`../docs/algorithms/gspo.md`](../docs/algorithms/gspo.md) 里明明写过
「不要只记录 mean，因为 mean ratio ≈ 1 不能排除 heavy tails」，然后自己就这么干了。

---

## 实测：mini=8（就是 R1 和 R2 用的配置）

`train_batch_size=16 / ppo_mini_batch_size=8`（2 个梯度步）、`lr=1e-6`、3 个 update。
指标来自新加的观测钩子（[`../scripts/patches/patch_ratio_stats.py`](../scripts/patches/patch_ratio_stats.py)，
纯观测，58 行插入 0 行删除）。

| | step 1 | step 2 | step 3 |
|---|---|---|---|
| **\|ρ−1\| 中位数** | 3.93e-06 | 1.91e-06 | 7.15e-06 |
| **\|ρ−1\| p95** | 0.0303 | 0.0279 | 0.0317 |
| **\|ρ−1\| p99** | **0.0555** | **0.0557** | **0.0568** |
| **\|ρ−1\| 最大** | **0.301** | **0.367** | **0.416** |
| ρ 最小 | 0.778 | 0.742 | 0.730 |
| ρ 最大 | 1.301 | 1.354 | 1.416 |
| ρ 标准差 | 0.0123 | 0.0120 | 0.0130 |
| **偏离 >1% 的 token 占比** | **7.99%** | **7.25%** | **8.72%** |
| 偏离 >5% 的占比 | 3.14% | 2.83% | 3.38% |
| 偏离 >20% 的占比 | 0.042% | 0.055% | 0.059% |
| `pg_clipfrac`（原生） | 1.27e-4 | 1.87e-4 | 3.76e-5 |

### 这个分布长什么样

**尖峰厚尾。** 中位数偏离 3e-6 —— 一半的 token 基本没动。但：

- **8% 的 token 偏离超过 1%**
- **3% 超过 5%**
- 极值到 ±30%~42%，而且**三步之内在持续变宽**（1.301 → 1.354 → 1.416）

均值 1.0001 完全是假象，它只是把 0.73 和 1.42 平均了一下。

## 两个结论，一个撤回一个保留

### 撤回：「GSPO 在这个配置下测不出东西」

**错的。** GSPO 的论点是：少数极端的 token ratio 会主导 clipping 和梯度，
而 sequence-level 的几何平均会把它们抹平。

现在看到的正是这种分布 —— 大部分 token 贴着 1，少数跑到 ±30% 以上。
sequence ratio $s_i = (\prod_t \rho_{i,t})^{1/\lvert y_i\rvert}$ 对这种情况的处理
跟 token-level 完全不同。**GSPO 这个臂有东西可测。**

补丁里已经同时给 GSPO 的 `seq_importance_ratio` 加了同样的观测
（前缀 `actor/seqratio`），所以真跑起来可以直接把两个分布摆在一起比。

### 保留：「clip-higher 没什么可作用的」，但理由换了

原来的理由（分布太窄）是错的。真正的理由是**带宽问题**：

clip-higher 把上界从 1.2 挪到 1.28，只影响落在 **(1.2, 1.28]** 这个窄带里的 token。
实测偏离 >20% 的占比只有 **0.04%~0.06%**，而这 0.05% 还要再被 (1.2, 1.28] 这个
更窄的区间切一刀。

所以 R2 里 clip-higher 改动前后 `pg_clipfrac` 几乎没动（5.2e-5→7.3e-5），
不是因为 ρ 不动，而是因为**能被这个改动碰到的 token 实在太少**。

顺带确认了原生 `pg_clipfrac` 是准的：它报 ~1e-4，我量的 `frac_gt_20pct` 是 ~5e-4，
同一量级（clipfrac 还要求 advantage 符号配合才算 binding，所以更小是合理的）。

## 对后面实验的影响

1. **GSPO 该跑，不用先改配置。** 现有的 `mini=8 / lr=1e-6` 就有足够的 ratio 离散度。
   之前说「必须先把 train/mini 比例拉大」是基于错误前提。
2. **要不要拉大比例，改成一个可测的问题。** mini=2（8 个梯度步）那个臂在跑，
   跑完就知道更多梯度步是不是真的让尾巴更肥。
3. **`ppo_kl` 这个指标以后只能当参考，不能当判据。** 带符号均值会骗人。
   判断策略偏移得看 `actor/ratio_absdev_p99` 和 `actor/ratio_frac_gt_*`。
4. **尾巴在三步内持续变宽**（max 1.30 → 1.42）值得盯 —— 20 个 update 的运行里
   这个量的走势可能比 reward 更早反映不稳定。

## 第二个臂：更多梯度步 = 更宽的分布，但 ppo_kl 纹丝不动

`mini=2`（8 个梯度步）对比 `mini=8`（2 个梯度步），其他全部相同：

| | mini8（2 步） | mini2（8 步） | 倍数 |
|---|---|---|---|
| \|ρ−1\| 中位数 | 3.9e-06 | 2.6e-05 | 6.5× |
| \|ρ−1\| p95 | 0.0303 | 0.0532 | 1.8× |
| \|ρ−1\| p99 | 0.0555 | **0.0992** | 1.8× |
| \|ρ−1\| 最大 | 0.301 | **0.701** | 2.3× |
| ρ 偏离 >1% | 7.99% | **14.5%** | 1.8× |
| ρ 偏离 >5% | 3.14% | **5.68%** | 1.8× |
| ρ 偏离 >20% | 0.042% | **0.116%** | 2.8× |
| **`ppo_kl`** | −4.9e-5 ~ +5.1e-5 | −7.5e-5 ~ +1.1e-5 | **基本不变** |

单调、干净：梯度步从 2 加到 8，分布宽度差不多翻倍。

**但最有价值的是最后一行。** 分布宽度翻了一倍，`ppo_kl` 还在同一个量级、
还是在 ±1e-5 附近来回翻符号。

这是对「`ppo_kl` 不能当分布宽窄判据」最干净的证明 ——
**它对分布宽度的变化根本不敏感**。两个宽度差一倍的分布，它给出几乎一样的读数。

以后判断策略偏移，只能看 `actor/ratio_absdev_p99` 和 `actor/ratio_frac_gt_*`。

### 对实验设计的影响

- **GSPO 用 `mini=8`（现有配置）就能跑** —— 8% 的 token 偏离 >1%，够了。
- 想要更强的信号，`mini=2` 能把离散度翻倍（p99 从 0.056 到 0.099），
  代价只是 actor update 时间，rollout 开销不变（前面探测测过 t_step 差异很小）。
- **clip-higher 即使在 mini=2 下也只有 0.13% 的 token 越过 20%**，
  而 (1.2, 1.28] 还是其中一小片。这条臂大概率还是测不出明显效果 ——
  但现在这个判断有分布数据支撑，不是从均值瞎推的。

## 教训

这是这个项目第二次踩「用均值推断分布」的坑，而且是在我自己写下警告之后。

第一次是 pre-RL rollout —— reward 均值 −0.746 看着像模型差，实际 512 条里只有 2 条真答错。
这次是 ratio 均值 ≈ 1 看着像策略没动，实际有 8% 的 token 跑出 1% 以外。

**均值不是分布。** 这句话在这个仓库里已经值两次教训了。
判断"有没有东西可测"之前，先把分布量出来 —— 成本是几行观测代码。
